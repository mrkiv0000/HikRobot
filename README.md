# Hikrobot — этап 3

Локальное приложение подключается как TCP-клиент к 1–4 камерам Hikrobot, собирает сообщения `{…}`, разбирает ID/X/Y/A, вычисляет SN и выполняет общий контрольный цикл по фиксированному окну времени.

## Реализовано

- Сохранены независимые подключения, настройки, статусы и сырой журнал этапа 1.
- Сохранены сборщик сообщений, строгий парсер, расчёт SN и история 10 наблюдений этапа 2.
- Первый корректный код открывает общий серверный цикл для выбранных камер.
- Окно имеет фиксированную длительность и не продлевается новыми пакетами или повторами.
- ID объединяются по точной строке; сохраняется первый результат с его X/Y/A/SN и камерой.
- Достижение ожидаемого количества не завершает цикл досрочно.
- Лишний уникальный ID показывает ошибку сразу, но сбор продолжается до срока.
- Недостаток определяется только после окончания окна.
- Таймер работает на сервере независимо от страницы и опроса API.
- NoRead суммируется по выбранным камерам и не считается разрывом связи.
- Потеря связи, ошибка формата или угла во время окна блокирует успех.
- «Отключить все камеры» отменяет активный цикл без искусственной ошибки недостатка.
- Завершённый успешный набор хранится внутри программы для следующего этапа, но строки ПЛК пока не формируются.

## Запуск в существующем окружении Windows

Остановите предыдущий сервер сочетанием `Ctrl+C` в его окне PowerShell. Новый venv создавать не нужно, зависимости не изменились.

```powershell
cd D:\OBJECTS\HikRobot
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 1
```

Откройте <http://127.0.0.1:8000> и один раз нажмите `Ctrl+F5`, чтобы обновить CSS и JavaScript.

Не используйте `--reload` и несколько workers: менеджер камер и серверный таймер должны существовать в одном экземпляре. Остановка сервера — `Ctrl+C`.

Если зависимости в окружении были удалены:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Настройки хранятся в `config\settings.json` и записываются только по кнопке «Сохранить настройки». Изменение ожидаемого количества и окна во время сбора применяется к следующему циклу. Чтобы применить другое количество камер или адреса при работающих соединениях, сначала нажмите «Отключить все камеры», затем подключитесь с новой конфигурацией.

## Ручное испытание с одной камерой

Подключите сохранённую камеру. Для каждого сценария дождитесь окончания предыдущего окна, убирайте лист и отпускайте кнопку/датчик, чтобы не создавать непрерывный поток новых циклов.

1. Установите ожидаемое количество `1`, окно `3` с. Прочитайте один ID. Должен идти отсчёт без раннего успеха; после полного окна — «Получено 1 из 1» и зелёный успех.
2. Установите ожидаемое количество `2`. Прочитайте один ID. До срока отображается сбор, после срока — ошибка недостатка 1 из 2.
3. При ожидании `2` покажите лист с двумя кодами. Оба уникальных ID должны появиться, успех — только после конца окна.
4. При ожидании `1` покажите два разных кода. Ошибка превышения 2 из 1 появляется сразу, но отсчёт продолжается, итог остаётся ошибочным.
5. При ожидании `2` сначала прочитайте один код, затем второй до срока. Срок от первого сообщения не должен измениться. Для удобства можно временно поставить окно `8` с, а затем вернуть `3` с. Если камера не выдаёт второй пакет в одном триггере, этот случай уже покрыт автоматическим тестом.
6. Повторите один ID внутри окна. Счётчик уникальных ID остаётся равным 1, а история получает повторное наблюдение. Тот же ID после завершения может открыть новый цикл.
7. Без активного окна выполните съёмку без кода. При одной выбранной камере `{NoRead}` должен сразу дать «Ошибка: Код не прочитан», без ожидания окна.
8. Во время сбора нажмите «Отключить все камеры». Результат — «Сбор отменён пользователем», позднего успеха быть не должно. Подключитесь снова и запустите новый цикл.
9. Во время сбора обновите или закройте страницу. После возврата отсчёт идёт от исходного старта; сервер фиксирует результат даже без открытого браузера.
10. Измените ожидаемое количество или окно во время активного сбора и сохраните. Текущий цикл сохраняет старый снимок, следующий использует новые значения.
11. Перезапустите Python. Настройки восстанавливаются, а история и результаты циклов начинаются пустыми.

Границы времени, ошибки углов, потеря связи и события 2–4 камер проверяются автоматически; вручную имитировать недоступное оборудование не требуется.

## Логика NoRead и связи

- NoRead части камер вне окна показывает ожидание остальных данных без таймаута.
- NoRead всех выбранных камер без кодов создаёт один результат «Код не прочитан».
- NoRead внутри активного окна не стирает коды и не завершает окно.
- Молчание подключённой камеры само по себе не блокирует успех, если суммарный набор корректен.
- Отключённая камера при старте либо разрыв во время окна блокируют успех.
- Повторное подключение не снимает уже зафиксированную ошибку текущего цикла.

Журнал ограничен последними 200 событиями. В нём отдельно видны сырые TCP-чтения, сборка/разбор, начало цикла, новые и повторные ID, NoRead, превышение, завершение и отмена.

## Автоматические проверки

```powershell
.\.venv\Scripts\python.exe -m pytest
```

Тесты используют управляемые часы и подмены сетевых вызовов, а не рабочий имитатор камеры. Они проверяют этапы 1–3, включая границу окна `[начало, срок)`, автоматическое завершение без API-опроса, уникальные ID, NoRead для 1–4 камер, блокирующие ошибки, снимок настроек, отмену и защиту нового цикла от старого таймера.

## Ограничения текущего этапа

- Таймер начинается от первого корректного кода, а не от внешнего датчика.
- Полное молчание камер не позволяет обнаружить пропущенную деталь.
- Поздний повтор после окончания окна может открыть новый цикл.
- NoRead разных физических деталей пока нельзя надёжно разделить без дополнительных признаков.
- Формирование `ID;SN\r\n`, TCP-сервер ПЛК, внешние запросы и разделение соседних деталей не реализованы.
